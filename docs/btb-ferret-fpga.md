# BOOM BTB-Ferret FPGA 测量

目标是在固定 checkpoint、预热和采样窗口下，测出有多少 FAuBTB miss 造成了本可早一拍避免的改向，这些 miss 是否相邻出现，以及一条和需求流量共享的主 BTB 读口能及时准备多少目标。设计依据为本地 [ass.md](../../btbferret/ass.md) 与 [论文](../../btbferret/BTB-FERRET_MICRO26.pdf) §III–V。论文研究的是串行的块级 L1→L2 BTB 访问和解耦前端。BOOM 的 F0 同时发起两级查询，FAuBTB 在 F1 给出目标，主 BTB 在 F2 给出目标，本实验针对这一级间的一拍差距。

## F3 如何确认一次机会

1. 同一个 F0 请求对齐到 F2。保存它的 F1 FAuBTB 槽位有效位和目标、F2 主 BTB 模块原始命中/类型/目标，以及 F1 影子缓冲查询结果。默认组合 F1 的目标由 FAuBTB 给出。主 BTB 的观测直接取模块内部响应，因此保留上一级目标的 F2 合并响应不会伪装成主表命中。
2. F2 把这些观察值和取指包一起入队。另记 F2 实际获胜的取指 PC、选择槽位、当前 replay 标记。严格改向要求已有的 F1 后继确实是这个包的顺序地址，F2 选择的目标不同，最终 F0 使用该目标。只有历史修复或没有有效 F1 后继的重新发起不进入机会计数。
3. 等 F3 预译码完成且取指包真正传入 F4 后才计数，每个包最多选一个重定向槽位。检查没有异常、预测响应有效、译码为直接 JAL 或预测 taken 的 BR。F3 用指令立即数计算目标，以该结果检查原始两级目标。JALR/返回仍可作为已选调用的触发来源，但动态目标在 F3 无法独立验证，故其自身不进入机会分母。
4. 在 F1 无目标时，区分主表无命中、主表命中但目标或分支类型不符、主表给出正确目标/类型。最后一类再筛出同一槽位、F2 实际改向、F1 原预测顺序、当前非 replay 的严格机会。I-cache/F4 反压期间不能重复计数。此前 I-cache/TLB 等待过的请求，若重新发起时没有 replay 标记且确实完成改向，仍可纳入，不能由此推断其整段访问没有缓存等待。
5. 给被选的 uop 附两位快照（严格机会和及时覆盖），只有 ROB 架构提交且没有归为 core 误预测才记 E16/E17。它滤掉最终被冲刷的路径和最终需 core 纠错的分支。F3 的 BR 只知道预测方向，退休这组数据更接近正确路径机会。两组来自不同流水阶段，短窗口边界可能有在途差异。

E7 衡量目标缺失，E8 单列 FAuBTB 有目标但与译码目标不符。E12 才是严格的一拍机会。E22 给出其中 JAL 数，BR 数为 E12−E22。E23 记录相邻的严格机会，要求上一观测包预计到达的 PC 与本包一致，前端 flush 清除链状态。可用 `E12−E23` 估计起链次数，用 `E12/(E12−E23)` 粗估平均链长，解释时留意窗口边界。这是预测流上的相邻包序列，粒度与论文的 block BTB 不同。它也没有完整的前驱类型直方图。

## 共享端口实验

- F3 消费包且最终选中 call 时，将 RVC/跨边界修正后的返回 PC 作为预取种子。选中后向、预测跳转的 BR 时，将落空 PC 作为种子。复用 RAS 写地址的长度与边界计算。缺少论文的 Alt 位，因此这是预测跳转后向分支的退出路径近似。
- 使用一项待发寄存器。主 BTB 对相应 bank 的需求始终优先。目标 bank 同拍没有真实需求读、没有写、没有初始化时才发预取读。复用现有 SRAM 读地址和读使能，只探候选 PC 的首 bank，预取响应绕开所有功能预测输出。等待期间后续种子可能被丢掉。
- 主表真实读取的目标和类型写入 8 项直接映射缓冲，以完整候选起始 fetch PC 比较，保存该 bank 的各槽响应。后续需求到达 F1 时旁路查询，结果写入后的下一拍才可见。F3 核对该快照与严格机会的槽位、类型和解码目标，完全匹配才计及时。错误或过期目标不影响取指。缓冲跨恢复保留，便于返回点和 loop 退出路径的观测。地址和目标都用现有 BTB 使用的虚拟地址，本实验不把缓冲接入功能。
- 严格机会到 F1 时，若同地址仍待发或正在返回而没有及时命中，则计 late。种子被丢、被覆盖、从未触发的机会不会进入 late。wrong_fill 计已有同地址槽位但内容不符，可能与 late 重叠。unused_eviction 表示被不同地址替换前未见 F1 地址查找，不能用于统计全部无收益填充。
- 当前预取不继续沿 BTB 响应扩展链，无 Alt 位、第二 bank 预取、独立端口对照或 F1 目标接管。及时覆盖因此只对应这套触发策略、实际共享读口和缓冲几何。观察到及时率低时，结合排队和发读计数区分端口饥饿与地址/缓冲覆盖不足。同台 FPGA 上仍需比较布线后的频率。新增 SRAM 地址 MUX、影子寄存器与计数逻辑均有实际资源和时序成本。

## 板上读数与实验对照

使用本目录对应的 `boom_scala` 生成 bitstream 并烧录，然后继续用板上已经验证可运行切片的读取程序采样。读取程序只需按编号输出 E0–E63，日志中的软件映射标记可以保留原样。输出含义以实际烧录的硬件版本为准，请记录 bitstream 版本。具有 `type` 与 `value` 字段的原 JSON 事件行可直接用下方命令解析。

```bash
cd /root/project/boom_stop
python3 log_process/read_counter/readlog.py /path/to/ferret-run.log docs/eventlist.ferret64-v1
```

1. 核对 E7=E9+E10+E11，E12+E13≤E9，E34+E49≤E12，E28≤E27，E17≤E16。E32 与 E28 跨一拍，窗口边缘允许一项在途。E53 的单位是 bank·周期，双 bank 时最大为 2×E0。
2. 先看 `1000×E12/E1` 和 `1000×E16/E1`，再看 E9/E7 与 E10/E7。E12 每千条指令给出严格定义下最多可提前的改向次数，可用一拍/次估数量级，无法直接换算 IPC。
3. 看 E23/E12、调用/循环种子数，及 E26/(E24+E25)。E12 大、E23/E12 大的切片可用于比较短链策略。
4. 用 E53/(bank数×E0) 看端口空闲率，E28/E27 看**确有待发任务**时的发读比例，E32/E28 看真实读回后的有效填充率。E27−E28 是共享调度无服务的待发拍数，含 bank 不匹配、写和初始化的限制。全局空闲拍和待发工作重叠多少，应以 E28/E27 为准。
5. 用 E34/E12 和 E17/E16 看共享模式的推测覆盖与退休覆盖，先看 E48/E22 评估从只接入 JAL 的原型起步。若 E12 高、E26 高、E28/E27 很低，优先验证独立目录或第二读口。若发读充分但 E34/E12 仍低，检查候选地址、缓冲冲突、单 bank 限制及 late/wrong_fill。样本统计无法单独决定独立读口的收益，应以同样的种子流和缓冲做 A/B 对照。

先跑 perlbench、gcc、deepsjeng 及可使 FAuBTB 驱逐而主 BTB 保持热的微基准。固定 checkpoint、预热、窗口和时钟，报告每样本原始计数与每千指令值，将缺失日志和超时状态显式区分。

## 本机实测

本节保留首次验证记录。验证时将 FPGA 观测逻辑适配至本地 Chipyard v3，并使用 MediumBoomV3Config 完整重编译 v3 源码，经过 Chipyard 展开、firtool、Verilator 5.030 和 C++ 链接。默认和 SFENCE 变体通过事件关系与指令结果校验测试，`rv64ui-p-jalr` 通过。单独的观察器定向仿真还覆盖了满队列丢弃/发读同时补入、返回同拍仍晚到、精确 PC/槽位命中、有使用和未使用的缓冲替换、空响应不填充。

同一 ELF 在修改前后 simulator 上的 E0/E1 完全一致，修改前二进制会被新事件关系测试识别。默认定向用例的候选很多，共享端口几乎一直被需求流量占用，不能靠增大待发队列解决。SFENCE 变体证明共享读、填充及及时退休覆盖能贯通，适合验证电路。两个数字组均需用真实 FPGA 切片重测后才能评估板上工作负载。

Medium 单 bank、4 槽、40 位地址的估算下，8 项影子缓冲本体约为 1,680 位，另有流水快照、待发寄存器、比较器和原 BTB 读地址 MUX。此估算未包含综合映射。此次验证未进行 Vivado 布线，整核 Fmax 和 LUT/FF 开销需由板端构建给出。
